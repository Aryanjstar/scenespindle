# Free-first production review — 2026-11-16

## Practical use cases

The shortest useful path is an authored explainer: import a validated storyboard, review its picture, supply or generate narration, align that audio, then export. An authored input avoids a mandatory planner subscription and keeps exact scripts under creator control. The current release adds portable HTML previews, not narrated exports. The next production priority remains measured narration and a verified MP4, followed by montage/talking-head inputs and targeted revisions. Series/3D must retain the gates in IMPLEMENTATION_PLAN.md.

## Alternatives and evidence

| Option | What it offers | Cost/constraints | Verification here |
| --- | --- | --- | --- |
| Authored JSON + offline preview | Local visual review with bundled fonts and runtime | No API key, account or provider calls; estimated silent timing only | CLI regression and two-creator browser journey |
| Ollama local planner | OpenAI-compatible chat and schema-constrained output | Local hardware and each chosen model's licence; no inference-service fee for local execution | Official API documentation reviewed; no local model/adapter benchmark performed |
| Kokoro local narration | Small open-weight speech model with multilingual voices | Model/voice rights and alignment quality need per-profile evidence; do not advertise Hindi/Hinglish parity from the voice list | Official voice documentation reviewed; current app has no production Kokoro adapter |
| Supplied narration + timed words | Preserves the creator's voice without voice cloning or paid TTS | Requires actual measured/aligned word times and asset provenance | Caption grouping exists; narrated import/export integration remains open |
| Existing local worker | MongoDB-leased background execution | Machine must remain running; no hosted worker spend | Preview queue, recovery, cancel/retry tested locally |

Sources: [Ollama OpenAI compatibility](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx), [Ollama structured outputs](https://ollama.com/blog/structured-outputs), [Kokoro voice inventory](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md).

## Hosting implications

[Vercel functions have bounded execution durations](https://vercel.com/docs/functions/configuring-functions/duration). Deploying the Next.js UI does not deploy the persistent Mongo worker. Retain the documented Azure/local worker architecture. The web preview compiler now builds HTML in memory, embeds fonts/runtime and does not write into the deployed application directory. UI fonts are installed assets, so builds no longer depend on Google Fonts being reachable.

## Dependency and contract review

Compatible locked updates remove the two high-severity advisories reported for Mongoose and follow-redirects. TypeScript is pinned to 6.0.3 because the installed typescript-eslint rejects 7.0.2. No new runtime package or provider was introduced. Eight moderate tooling dependency advisories remain; forcing npm's proposed Next ESLint downgrade is not a verified fix.

Cross-check: owner-scoped routes and immutable storyboards retain their existing behavior; output remains explicitly silent/estimated. No provider or quota bypass is introduced. Full PRD acceptance remains open, particularly MP4, rate limiting/reset, durable planning, storage, budgets, deletion retention and advertised capability coverage. This review does not mark those requirements complete.
